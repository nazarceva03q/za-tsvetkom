# Актуальная схема каталога — 19.10.2026

Каталог и фото перенесены в локальной реализации на REG.RU. Установка ещё
предстоит: следуйте [REG-CATALOG-SETUP.md](../docs/simplified/REG-CATALOG-SETUP.md).
Боту нужны `REG_CATALOG_URL` и отдельный `REG_CATALOG_SECRET`. Приватный
`YC_S3_BUCKET` остаётся для состояния бота; публичный бакет не нужен.
Упоминания публичного бакета в прежних разделах ниже описывают старую схему
и не являются текущими инструкциями установки.

# Бот «За цветком» для ВКонтакте

Node.js 22+. Бот работает в личных сообщениях сообщества через VK Callback API.
Управление товарами доступно только VK_OWNER_ID и VK_ADMIN_IDS. Покупатели
могут задать вопрос, оставить телефон и получить ответ администратора.

## Настройка ВК

1. Включите сообщения сообщества и возможности ботов. Создайте токен сообщества
   с правами на сообщения и фотографии. Не используйте личный токен.
2. Скопируйте .env.example в .env. Заполните VK_GROUP_TOKEN, VK_GROUP_ID (положительный
   числовой ID сообщества), VK_OWNER_ID (ID личной страницы владелицы), VK_ADMIN_IDS
   (другие администраторы через запятую, необязательно).
3. В настройках сообщества «Работа с API → Callback API» создайте сервер.
   Версия API 5.199. Задайте секретную строку и скопируйте её в VK_CALLBACK_SECRET.
   Строку, которую должен вернуть сервер при подтверждении, запишите в VK_CONFIRMATION_TOKEN.
4. Разверните код и укажите полный HTTPS-адрес в настройках Callback API:
   VM: https://ваш-домен/webhook/vk; Cloud Functions: URL самой функции.
   Этот же адрес можно записать в PUBLIC_SERVER_URL для локальной проверки настроек.
5. Подтвердите сервер. Включите события message_new и message_event.
   Сервер возвращает строку подтверждения или обычный текст ok, как требует Callback API.
6. Владелица и каждый администратор должны написать сообществу «Начать».
   Бот работает в личных сообщениях; события из групповых бесед игнорируются.

node scripts/setup-webhook.js проверяет локальные поля и показывает инструкцию;
он не регистрирует сервер автоматически и не отправляет сообщения пользователям.
Без правильного секрета и ID сообщества webhook отклоняет события.

## Хостинг

Обычный Node.js-хостинг: в папке bot выполните npm start (установка пакетов не нужна).
Встроенный HTTP-сервер Node.js слушает PORT (по умолчанию 3100). Публичный HTTPS обеспечивает хостинг.
Процесс должен принимать запросы постоянно; хостинг может управлять им самостоятельно.

Без постоянного процесса: node scripts/build-yandex-zip.cjs, затем загрузите
yandex-deploy.zip в Yandex Cloud Functions. Среда Node.js 22+, точка входа index.handler,
таймаут 120 секунд, переменные из .env.example, публичный HTTPS-вызов.
Обработка завершается до ответа webhook. VK может повторить запрос при медленном ответе;
успешные события запоминаются и повторно не обрабатываются.

Хранилище использует JSON-файлы с операциями чтение/изменение/перезапись.
Поэтому запускайте ОДИН процесс/экземпляр функции с одним одновременным вызовом.
Внутри процесса запросы обрабатываются последовательно. Несколько экземпляров
без транзакционной БД могут перезаписать изменения друг друга.
Для высокой нагрузки и быстрой очереди webhook потребуется отдельная очередь задач и БД.

## Yandex Object Storage

YC_S3_BUCKET — закрытый бакет для сессий, вопросов, клиентов, заявок и ID
обработанных событий. Обязателен для Cloud Functions. На обычном сервере без него
используются файлы bot/data на постоянном диске.

YC_PUBLIC_S3_BUCKET — отдельный публичный на чтение бакет для catalog.json и фото.
YC_S3_ACCESS_KEY и YC_S3_SECRET_KEY — статический ключ сервисного аккаунта с правами
на оба бакета. Не публикуйте ключи на сайте.

Первоначальная настройка из папки bot:

    node scripts/migrate-products.js
    node scripts/configure-cors.js

Миграцию выполняйте только один раз: она перезаписывает каталог исходными товарами сайта.
В index.html сайта заполните content у meta name="catalog-url" публичным адресом:
https://storage.yandexcloud.net/ИМЯ-БАКЕТА/catalog.json
Сайт читает каталог при открытии страницы без браузерного кэша. После изменения
товара обновите страницу. Без URL или при ошибке загрузки остаётся статический каталог.

## Меню администратора

- Добавить/изменить товар: категория, фото, название, состав, описание, цена,
  количество, отметка «Хит», предпросмотр и сохранение.
- Для бизнеса: фото с отдельной ценой для каждого; диапазон цен считается автоматически.
- Удалить товар: удаляет запись из каталога. Фото в бакете сохраняются.
- Управление количеством: число либо прочерк для товара под заказ.
- 🔥 Хит: найти товар, поставить или снять отметку. Хиты идут первыми в своём разделе.
- Заявки: последние 500 обращений. Ответ покупателю — кнопкой «Ответить» под вопросом.

Фото из ВК скачиваются в Object Storage. Для показа фото в сообщении бот загружает
его через photos.getMessagesUploadServer и photos.saveMessagesPhoto. Если прикрепить
фото не получилось, карточка приходит текстом. Длинные тексты и клавиатуры разбиваются
на несколько сообщений. Телефон покупатель вводит текстом.

## Проверки

Из папки bot: npm test. Проверки работают без токенов, сети и настоящего бакета.
После изменения кода пересоберите ZIP. В архив не попадает .env.
Без доступа к настроенному сообществу и бакетам реальную доставку сообщений проверить нельзя.
