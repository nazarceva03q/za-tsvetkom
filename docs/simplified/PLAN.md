## Новое решение
REG.RU сохраняет все типы заявок: корзина, подбор, большой букет, корпоративные подарки, предзаказ, общий вопрос и другие существующие формы.
Сохраняются контактные данные, выбранный способ связи, пожелания, дата, доставка (если запрошена), бюджет/количество, текстовые названия товаров и их количества. Фото и подтверждённые цены не требуются. Названия из браузера — сведения заявки, не доверенная карточка товара.
Каталог и бот остаются на Яндексе. Изменения административного каталога не требуют переноса в MySQL.
Сначала заявка + позиции + очередь фиксируются одной транзакцией; затем независимый CLI cron на REG.RU передаёт уведомление защищённому обработчику Yandex Functions, который вызывает VK.
Нельзя отправлять напрямую из браузера или хранить секрет в JS. Яндекс недоступен — заявка остаётся в панели; очередь повторяет попытку.
Сохраняем ранее согласованное ограничение: в VK нет имени, телефона, адреса, комментариев. Уведомление содержит номер, тип и товары/количество; контакты доступны Екатерине в защищённой панели.
Обычные покупатели пишут в сообщество без автоматических ответов; административные диалоги сохраняются. Старый публичный обработчик phone на функции закрывается.

## Дизайн панели
Назначение: Екатерина быстро видит новые обращения и открывает контакты. Список → карточка → звонок; не таблица администрирования MySQL.
Белый #ffffff, фон #f5f7f5, текст #20372b, основной зелёный #285b43, граница #d7e1da, ошибка #9c2535. Системный sans-serif для работы; Georgia только заголовок магазина. Ширина до 960px, одно столбцовое чтение на телефоне, явные подписи и фокус. Без внешних шрифтов/зависимостей, без анимаций.
Простой рабочий список выбран вместо декоративного dashboard: в задаче важнее заявки и контакт, чем графики. На карточках тип словами, дата Перми, номер и краткая тема. Без выдуманной итоговой суммы.
