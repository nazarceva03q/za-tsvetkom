# Статусы, следующие действия и очистка: подготовлено локально

## Что готово
Миграция 004 добавляет служебные поля заявки и таблицу минимальной истории. Статусы: новая, в работе, ожидаем клиента, выполнена, отменена, без покупки. Следующее действие имеет срок по Перми; база хранит UTC. Уведомления VK и сохранение заявки не подтверждают покупку. Для «Выполнена» нужно явное подтверждение владельца.

Изменение состояния и событие записываются одной транзакцией. Версия формы защищает от потери изменений при двух вкладках; Origin, сессия и CSRF проверяются до записи. Список поднимает претензии, просроченные действия и новые обращения. Это список внутренних задач, а не отправка сообщения покупателю. Автоматических напоминаний сотруднику вне панели в этом этапе нет.

При закрытии заявки или открытии претензии назначенное действие отменяется. Работа по претензии требует человека; автоматический срок пересмотра претензии пока не реализован. После повторного открытия дата закрытия сбрасывается. Первая подтверждённая покупка остаётся отмеченной даже при последующей смене статуса, чтобы не попасть под очистку «без покупки».

## Очистка: ещё не включена
retention.approved=false и retention.enabled=false по умолчанию. 30 дней — предложенное правило только для закрытых без покупки/отменённых обращений, не универсальный срок для заказов. Утвердить цель, момент закрытия и срок перед применением. Для выполненных покупок, старых записей и претензий автоматическое удаление не делается: там требуется отдельная оценка оснований/сроков.

CLI bin/retention.php без аргументов только считает кандидатов, причём требует утверждённого правила. --apply дополнительно требует enabled=true и backup_procedure_approved=true. Не подключать cron до утверждения и проверки. За запуск не более 100 кандидатов. Каждая запись заново проверяется и блокируется транзакцией. Активная отправка queue.status=processing блокирует очистку, даже если lease истёк: сначала выяснить, завершилась ли передача.

Для подходящей заявки удаляются позиции с JSON-снимками, очередь с message_text и старая история. Очищаются имя, телефон, тема, адрес, пожелания, дата получения, бюджет/количество, канал и суммы. Сохраняется ограниченная служебная запись с номером/ключом повторов, версией/контрольной суммой согласия и датами; она псевдонимная, не анонимная. Срок и основание хранения этой записи и минимального события очистки необходимо согласовать отдельно. Повтор старой отправки не создаёт вторую заявку: изменённый хеш выдаёт конфликт ключа.

Это очистка активной MySQL, а не гарантия удаления из любых копий. До approval нужны порядок резервного копирования/восстановления, повторное применение удалений после восстановления, проверка журналов и внешних квитанций. Флаг backup_procedure_approved не выполняет эти операции сам. Сервисные rate/login/session-таблицы требуют отдельной процедуры очистки истёкших записей.

## Порядок установки на REG.RU (пока не выполнен)
1. Приём оставить выключенным. Сделать свежий экспорт базы, проверить имя u3685169_default и сохранить копию закрытой конфигурации вне www с ограниченными правами. Никаких секретов в Git/чат.
2. Применить только 004 один раз после уже выполненной 003. При ошибке проверить структуру и не повторять вслепую. 001–003 не повторять.
3. Обновить private-orders/lib/Owner.php, RequestView.php, добавить Workflow.php. Обновить публичные owner/orders.php и orders.css. Не перезаписывать config.php шаблоном. Сначала схема, затем код, затем включение.
4. В config.php добавить 'workflow'=>['enabled'=>true], только после миграции/загрузки; блок retention скопировать с false из config.example.php. Не менять существующие DSN, пароль, секреты и consent_version. notifications и общий приём оставить выключенными до своего этапа.
5. php -l для файлов; проверить вход/выход, тестовую заявку, смену статуса, назначение срока, конфликт двух вкладок, отсутствие доступа без сессии. Операции тестировать на согласованных тестовых данных. До настоящего приёма утвердить и проверить процедуру хранения/удаления и отдельное согласие.
6. Для установки retention.php загрузить его только в private-orders/bin. Не создавать публичный URL; chmod 600 для config.php сохраняется. Начать с режима подсчёта, удаление выполнять отдельно после проверки политики и резервных копий.
