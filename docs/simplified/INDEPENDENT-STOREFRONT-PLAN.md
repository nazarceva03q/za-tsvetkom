# Корректировка независимости витрины — 19.10.2026

Пользователь уточнил: сайт должен продолжать корректно показывать каталог, фото и количество, включая последующие изменения из бота, при недоступном Яндексе. Прежний план обеспечивал независимость заявок/панели, но публичный каталог и новые фотографии предполагал в Object Storage. Это НЕ полная независимость витрины.

## Согласованная целевая схема (локальный код готов, на сервере не установлен)
REG.RU — основной источник каталога, фотографий, остатков и заявок. Сайт читает каталог с того же домена, фото также находятся на REG.RU. Бот работает в Яндексе и выполняет операции через отдельный защищённый API REG.RU. Секрет никогда не передаётся в браузер.

Операция из бота считается успешной только после подтверждённой записи на REG.RU. Повтор использует ключ операции, конфликт версий не затирает работу другого администратора. Фотографии проверяются сервером, сохраняются до публикации версии каталога; при сбое старая версия остаётся целой. Изменение названия, цены, количества, хита, фото, добавление и удаление должны идти через тот же источник. Нельзя оставлять разные пути записи отдельных полей.

Исходные 53 товара/89 фото-ссылок сохранить при первом переносе, без сброса каталога и ID. Новые внешние фото копировать на REG.RU, а не оставлять ссылкой на Яндекс. Резервные копии должны включать каталог и фото. Настроить очистку временных загрузок и лимиты диска/размера; секреты и серверные модули вне www. Запрос на добавление товара не даёт права загрузить произвольный исполняемый файл.

При сбое Яндекса витрина, фото, корзина, приём заявок и панель продолжают работать при доступном REG.RU. Бот и уведомления могут быть недоступны. Новые изменения, которые не дошли до REG.RU, не считать сохранёнными. Для редактирования товаров также во время сбоя Яндекса понадобится отдельный интерфейс каталога на REG.RU — текущая панель показывает заявки и такого редактора не содержит.

Автоматическое уменьшение остатков после отправки заявки НЕ требуется и не реализуется: заявка не подтверждает продажу и не резервирует товар. Остаток задаёт администратор; покупка/резервирование требуют отдельного процесса. Недоступность VK не должна блокировать сохранение заявки.

## Что сделано в текущей проверке
Исправлены подключение config в обработчике «Заявки» и точная подсказка количества. Добавлены проверки неотрицательного целого остатка, недопустимости успешного ответа для удалённого товара/сбоя записи, отказа от пустого повреждённого каталога и конфликта конкурентных правок. Подготовлены защитные изменения загрузчика: запуск после deferred-скриптов, валидация данных до замены, сохранение корзины при отложенной загрузке, отсутствие молчаливого показа устаревшего остатка как актуального. Они сами не подключают публичный бакет или REG API.

## Пока не делать
Не создавать публичный бакет и не ставить в catalog-url адрес Яндекса до решения по этой корректировке. Не запускать публикацию или импорт поверх работающего каталога. Приватный бакет уже используется для состояния бота/квитанций и остаётся отдельной частью; его существование не делает сайт зависимым от него для чтения каталога.

Подготовлены защищённый API каталога/фото REG.RU, адаптер бота, начальный seed и установочная CLI без перезаписи существующего каталога. Проверен цикл реального кода бота через PHP API: количество, цена, название, фото, Хит, добавление/удаление, повторы и конфликты. Браузерная проверка витрины с локальным каталогом проходит при заблокированных внешних запросах. Поиск бота предлагает товары с перестановкой слов и распространёнными падежными окончаниями.

Следующий этап — [серверная установка](REG-CATALOG-SETUP.md). Текущие правки локальные, не опубликованы. Прежние 94% относились к старому объёму работ; перенос каталога/фото меняет объём, новый точный процент не определён. Автоматическая очистка осиротевших фото пока не реализована: до её отдельной настройки файлы не удаляются.
