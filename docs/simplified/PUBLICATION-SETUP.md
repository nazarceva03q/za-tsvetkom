# Безопасные обновления через GitHub

Новый .github/workflows/deploy-reg.yml подготовлен в simplify/requests-reg-yandex. Пока ветка не слита в main, работающий старый workflow main НЕ заменён. Push этой ветки не публикует сайт. Не запускать старый workflow вручную и не сливать в main до проверки готовности сервера.

Обновление сохраняет автоматический запуск при push в main. По умолчанию он только проверяет список и не подключается к FTP. Для отправки нужны repository variables SITE_DEPLOY_READY=true и проверенный FTP_WEB_ROOT. Не включать SITE_DEPLOY_READY, пока API, документы, закрытая конфигурация и тестовый приём не готовы. workflow_dispatch dry_run=true также никогда не публикует. Ручная реальная отправка разрешена только из main с тем же переключателем готовности.

FTP_HOST/FTP_USERNAME/FTP_PASSWORD — прежние GitHub Secrets. Не присылать значения в чат. FTP_WEB_ROOT задаёт проверенный абсолютный путь в файловой системе именно FTP-учётной записи; это не обязательно /var/www/... из shell. Его нужно проверить отдельно в FTP. Скрипт не угадывает и не создаёт целевой корень. До проверки не ставить / просто по предположению.

Список scripts/publish-storefront.py разрешает конкретные корневые файлы витрины, legal.html и consent.html (последний только если существует), изображения из assets/images и шрифты из fonts. .htaccess, PHP API/панель, backend, bot, SQL, тесты, архивы, конфигурация и данные не передаются. Приватные модули и публичные PHP устанавливаются вручную по инструкции отдельного этапа. Изображения проверяются по расширению, symlink в выбранном пути запрещён. Контент репозитория по-прежнему должен проходить ревью перед merge.

Используются FTPS, проверка TLS-сертификата/имени и зашифрованный канал данных. Удаления удалённых файлов нет, поэтому старые случайно опубликованные файлы этим скриптом не убираются. Перед включением проверить публичную папку на наличие закрытых файлов/архивов отдельно. Главный index.html отправляется последним. Обновление не атомарно: резервная копия и проверка сайта после публикации обязательны.

Проверки: 6 локальных тестов с подставным FTP (без сети), реальный dry-run выбрал 148 публичных файлов. Проверены запрет закрытых путей и архивов, недостающий файл, неверный корень, выключенная/неполная конфигурация и TLS-настройки. Настоящая учётная запись FTP не использовалась. Первый сетевой запуск проводить только после согласованной готовности.
