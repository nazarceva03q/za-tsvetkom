# Каталог на REG.RU — установка после локальных проверок

19.10.2026. Согласованная схема: REG.RU хранит актуальный каталог и фото,
Яндекс выполняет команды бота. GitHub обновляет код витрины. Приватный бакет
Яндекса остаётся для сессий бота и квитанций уведомлений. Публичный бакет не нужен.

Код подготовлен и проверен локально. Это не подтверждение установки на сервер.
Приём заявок и уведомления нельзя включать автоматически вместе с каталогом.

## Порядок установки

1. Сохранить копию текущих файлов сайта и `private-orders` вне публичной папки.
   Заполненный `config.php` и резервные копии не отправлять в чат/GitHub.
   Эта установка файловая: новой миграции MySQL не требуется.
2. Локально выполнить `node bot/scripts/migrate-products.js`. Получится
   `bot/catalog.seed.json`: 53 исходных товара, 89 ссылок на существующие фото.
   Использовать этот seed только для первого запуска. Если товары уже менялись
   в другом динамическом каталоге, сначала сверить и перенести актуальные данные.
3. Загрузить `backend/orders/lib/Catalog.php` в `/private-orders/lib/Catalog.php`,
   `backend/orders/bin/init-catalog.php` в `/private-orders/bin/init-catalog.php`,
   seed в `/private-orders/catalog.seed.json`.
4. В существующий массив `config.php` добавить отдельный блок (остальное сохранить):

   ```php
   'catalog' => [
       'enabled' => false,
       'secret' => '',
   ],
   ```

   Сгенерировать новый отдельный секрет: `/opt/php/8.3/bin/php -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'`.
   Вставить результат в `catalog.secret`. Это не VK_CALLBACK_SECRET,
   не SITE_RELAY_SECRET и не ключ Object Storage. Секрет не показывать.
5. Проверить синтаксис `config.php`, `lib/Catalog.php`, `bin/init-catalog.php`
   командой `/opt/php/8.3/bin/php -l ПУТЬ_К_ФАЙЛУ`.
6. Инициализировать один раз из Shell:

   ```sh
   /opt/php/8.3/bin/php "$HOME/private-orders/bin/init-catalog.php" "$HOME/private-orders/catalog.seed.json" "$HOME/www/xn----ctbjb9aqim7a5cq.online"
   ```

   Ожидается `CATALOG_INITIALIZED`. Проверяются все фото на сервере.
   Существующий каталог не перезаписывается. Создаются приватная папка
   `/private-orders/catalog` и публичная `/assets/catalog` для новых фото.
7. Загрузить `api/v1/catalog.php` в папку сайта `/api/v1/`. Сохранить существующую
   настройку `ZT_ORDERS_PRIVATE_DIR` в `.htaccess`. Включить только
   `catalog.enabled => true`, повторно проверить синтаксис.
8. Открыть `https://цветы-пермь.online/api/v1/catalog.php`. Должен вернуться
   каталог из 53 товаров, а не ошибка или пустой объект. Публичное чтение
   показывает только товары; конфигурация и история операций остаются приватными.
9. В Яндекс добавить `REG_CATALOG_URL` =
   `https://xn----ctbjb9aqim7a5cq.online/api/v1/catalog.php` и
   `REG_CATALOG_SECRET` = тот же новый секрет из `catalog.secret`.
   Загрузить обновлённый `bot/yandex-deploy-simplified.zip`. Сохранить все ранее
   настроенные переменные, Node.js 22, `index.handler`, таймаут 20 секунд.
   Проверить, что загружен `src/catalogClient.js`. Старый ZIP этого модуля не содержит.
10. Через бота изменить количество одного согласованного товара, проверить GET
    каталога, вернуть исходное значение. Ошибка 403 при верном секрете требует
    проверки передачи `Authorization` через FastCGI. При необходимости добавить
    в `.htaccess` `SetEnvIf Authorization "^(.+)$" HTTP_AUTHORIZATION=$1`.
    Не помещать секрет в URL или JavaScript.
11. Загрузить обновлённые `app.js`, `catalog-sync.js`. Проверить в новом `index.html`
    `<meta name="catalog-url" content="/api/v1/catalog.php">`, обновить версию
    ссылки на `app.js` и добавить новую версию ссылки на `catalog-sync.js`.
    Новый index.html загружать только после готовности API; эта настройка уже сохранена в исходном коде и не должна сбрасываться при обновлении из GitHub.
12. Проверить на сайте: название, цена, фото, количество, ноль в наличии, Хит,
    добавление и удаление тестового товара. Обновить страницу после команды.
    Выбор товара в заявке не уменьшает остаток: заявка не подтверждённая продажа.
13. Проверить без доступа браузера к Яндексу: каталог и фото должны загружаться
    с REG.RU. Отдельно проверить сохранение заявок после разрешённого запуска
    приёма заявок. Доставку Екатерине проверить после разрешения сообщений сообщества.

## Сохранность и GitHub

Актуальные данные: `/private-orders/catalog/state.json`; фото бота:
`/www/ДОМЕН/assets/catalog/`. Делать резервные копии обеих папок и исходных
фото витрины. Не размещать state/config в публичной папке. Права приватной
папки 700, state/config 600; статические фото 644. Не запускать удаление фото:
они могут использоваться другими товарами или резервными копиями.

`scripts/publish-storefront.py` не удаляет файлы назначения и не публикует
приватные данные/PHP. Генерируемые каталог и фото не являются частью исходных
данных GitHub. Не добавлять их в репозиторий и не применять FTP-режим очистки.
Безопасный workflow пока в ветке `simplify/requests-reg-yandex`: перед слиянием
в main проверить настройки публикации. Старый workflow main не считать проверенным.

Запись каталога: блокировка, проверка версии, атомарная замена одного файла;
две параллельные правки не теряют изменения молча. Последние 100 успешных
операций имеют квитанции повторов в том же файле. Фото получают имя по хешу
содержимого; повторная загрузка возвращает ту же ссылку. Загрузка фото сама
не публикует товар: сначала фото, затем проверенный каталог.

При сбое Яндекса сайт читает последнюю успешно сохранённую версию на REG.RU,
включая добавленные ботом товары и фото. Управление через бот и уведомления
через Яндекс временно недоступны. Это не защита от сбоя самого REG.RU: при
ошибке его API витрина показывает предупреждение и резервные товары, а
точные остатки не выдаёт за актуальные. Панель REG.RU пока управляет заявками,
отдельного редактора товаров в ней нет.
