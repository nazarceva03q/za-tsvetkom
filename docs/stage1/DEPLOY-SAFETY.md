# Проект безопасной публикации — не применён

Текущий `.github/workflows/deploy-reg.yml` оставлен без изменений.
`deploy-reg.proposed.yml` — только текст для согласования, GitHub его не запускает.
Разработка ведётся в локальной ветке `stage1/orders-mysql`, без commit/push.
В рабочей папке до начала работы уже были изменения app.js, index.html,
refinement.js и новые bot/, catalog-sync.js, package.json, tests/.

## Обязательные условия перед публикацией

1. С отдельного разрешения заменить старый workflow; не добавлять второй рядом:
   старый иначе продолжит автоматически публиковать main.
2. Проверить FTP_WEB_ROOT — фактическую публичную папку именно этого сайта.
3. Настроить environment production и, если доступно, обязательное одобрение.
4. Сначала выполнить dry_run; публикация только вручную после согласования.
5. Список в проекте разрешает только перечисленные файлы витрины. Ни обхода
   всего репозитория, ни удаления удалённых файлов. Все фотографии, assets/,
   uploads/, bot/, backend/, api/, конфигурация, SQL, архивы, логи и данные
   исключены самим отсутствием в списке. Этот проект предназначен для
   обновления существующего сайта: первичную загрузку ресурсов он не делает.
6. PHP API, закрытые исходники сервера и конфигурацию публиковать отдельно,
   вручную, по проверенному перечню. Рабочую БД не затрагивает FTPS.
7. Сохранить резервную копию текущего кода и БД. Подготовить короткое окно
   обслуживания: последовательный FTPS не обеспечивает атомарную публикацию.
8. Сначала БД и API, затем витрина. Проверять каждую ступень; до готовности
   приём выключен конфигурацией. Снимок каталога лежит вне публичной папки.
9. Откат витрины — на подготовленную версию с честным отказом приёма, никогда
   на старую ложную надпись «заявка отправлена». Новые заказы не удалять.

## Почему пока нельзя публиковать ветку

Старый workflow публикует почти весь репозиторий, включая новые PHP, SQL и
тестовые файлы. Нельзя переносить эту ветку в main или запускать старый
workflow до отдельного согласования защиты публикации. Даже после замены
workflow проверить все другие пути публикации и область доступа FTP.

Ни этот проект, ни дальнейшие инструкции не разрешают запуск деплоя.
