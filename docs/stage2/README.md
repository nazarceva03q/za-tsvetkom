# Локальный этап: VK-уведомления и закрытый просмотр

Реализовано без изменения сайта на сервере, действующего VK-бота, каталога и workflow.

## Файлы

- backend/orders/migrations/002-owner-notifications.sql — дополнительные поля очереди, таблицы сессий и ограничения входа. 001 не изменена.
- backend/orders/lib/Notifications.php — формирование сообщения только из номера, даты, товаров и суммы; VK transport, разбор ответа, захват задания с lease и повторные попытки.
- backend/orders/bin/notify.php — закрытая CLI-команда cron, максимум 10 заданий за запуск.
- backend/orders/lib/Owner.php и owner/orders.php — вход, список по 50 заказов, полная карточка, состояние уведомления, выход. Только просмотр, без изменения заказов и каталога.
- backend/orders/config.example.php — дополнен выключенными по умолчанию разделами vk и owner.
- tests/orders-notifications.php — локальные проверки очереди и ошибок VK; тестовый стенд дополнительно проверяет HTTP-вход.
- Эта папка — инструкция и результаты.

Сессии: случайный токен в Secure/HttpOnly/SameSite=Strict cookie, в MySQL только SHA-256 токена, срок 8 часов, отзыв при выходе. POST защищены CSRF и точным Origin. Ограничение 10 попыток входа на 15-минутное окно по HMAC адреса; на границе окна возможно удвоенное число попыток. На общей сети пользователи делят ограничение. SQL подготовленные, вывод экранирован, CSP запрещает скрипты и встраивание. Нет публичного получения заказа по номеру.

Отправка не входит в транзакцию оформления: заказ уже сохранён. Задание блокируется короткой транзакцией; сеть вызывается после commit. Текст, получатель и random_id фиксируются перед первой попыткой и сохраняются при повторе. Изменение конфигурации получателя не перенаправляет уже подготовленные задания. Два запуска не забирают одну действующую блокировку. Обновление результата проверяет токен блокировки. При потере соединения после фактической отправки следующий запуск использует прежний random_id.

Временные сетевые ошибки, некорректный ответ и временные коды VK повторяются с задержкой от минуты до часа и небольшим случайным сдвигом. Ошибки прав/токена и неизвестные ошибки требуют проверки. Автоматических бесконечных повторов нет. Слишком длинное сообщение остаётся failed; доступ к заказу сохраняется. Обращения без товаров отправляются как «Обращение», с нулевой суммой товаров; содержание обращения и контакты доступны только в закрытой карточке.

Токен VK, пароль MySQL и хеш пароля владелицы находятся только вне публичного каталога. Логи не содержат их, HTTP-ответы VK или контакты покупателей. Рабочие значения необходимо настроить вручную, не в переписке.

Порядок запуска и отката: REG-RU-SETUP.md. Рабочая база не изменялась. Публикация, commit, push и Actions не выполнялись.
