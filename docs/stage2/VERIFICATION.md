# Результаты локальной проверки

Проверка: 16 октября 2026 года. Никаких обращений к рабочему сайту, базе REG.RU или VK для отправки сообщений не выполнялось.

## Окружение

PHP 8.3.33 в WebAssembly и настоящий отдельный MySQL 8.0.46, привязанный только к 127.0.0.1. Отдельный новый каталог данных, отдельный порт, только синтетические заказы. Службы Windows не устанавливались. Сервер после проверок остановлен. Это не проверка FastCGI/Apache и не выполнение cron в ISPmanager.

SQL 001 и 002 применялись только в одноразовой тестовой базе. Проверены синтаксис PHP и выполнение кода с реальным PDO/MySQL. Сетевой доступ PHP ограничен единственным локальным портом тестовой MySQL.

## Проверено

- 28 проверок отправщика и очереди: блокировка задания, повторный запуск, восстановление истёкшей блокировки с теми же random_id/текстом, отсутствие повторной отправки sent, временная ошибка и задержка, постоянная ошибка VK, успешное завершение.
- Разбор настоящего формата VK API на подставленных ответах: ошибка сети, HTTP 500, некорректный JSON, отсутствующий response, ошибки 6/901/5 и успешный message_id.
- Исключение имени, телефона, адреса, комментария и темы обращения из уведомления; наличие товаров/количества/суммы, перевод UTC во время Перми.
- 15 проверок закрытого просмотра через публичный PHP gateway: HTTP запрещён, анонимный просмотр запрещён даже по ID, no-store/CSP, защищённый cookie, CSRF, чужой Origin, неверный пароль, успешный вход, список и полная карточка, вредоносный HTML экранируется, выход, отзыв cookie, ограничение попыток, недоступная база.
- Повторно пройдены 12 серверных проверок оформления заказа, включая согласованность записей, откат при ошибке очереди, одинаковый ключ, подмену цены, несуществующий товар, ошибку базы, повтор после потерянного ответа.
- 8 одновременных запросов с одним ключом на SQL-уровне: один заказ, остальные отклонены уникальным ограничением.
- 10 тестов браузерного клиента и тесты реальных форм в локальном Chrome с подставленными ответами API: корзина/поля сохраняются при ошибках, ложного успеха нет, товары под заказ оформляются.
- Сохранены 29 защищённых файлов первого этапа, каталог 53/89; 8 контрольных файлов ранее незакоммиченной работы совпадают с сохранёнными хешами. Ветка stage1/orders-mysql, main не изменена.

Доказательства: evidence/local-tests.json, evidence/prior-work-preservation.json; прежние проверки — docs/stage1/evidence.

## Воспроизведение стенда

Исходник DB-проверок: tests/orders-notifications.php. HTTP-модуль: tests/orders-owner-lab.mjs, экспорт runStage2(php, {root, dsn, user, password}). Он требует подготовленный изолированный PHP-WASM стенд и одноразовую локальную MySQL со схемой zt_test_orders_php_review после базовых тестов первого этапа. Модуль не является самостоятельной production-командой; повторное применение 002 в той же схеме намеренно завершится ошибкой.

Использованный локальный оркестратор: C:/Users/User/Desktop/Projects/.zt-orders-lab/run-mysql-review.cjs; он создаёт свежий datadir и тестовые схемы, запускает базовые тесты, затем модуль второго этапа и останавливает сервер. Зависимости находятся только в этом каталоге, не в проекте сайта. Учётные данные тестовой базы в отчёт не копируются.

Недоступность базы проверена через отказ подключения к несуществующей тестовой схеме. Остановка рабочего MySQL/сетевые сбои хостинга не моделировались. В одном из повторов выявилось ограничение PHP-WASM при ошибочной аутентификации MySQL; сценарий отказа базы проверен без этого дефекта тестового рантайма. На REG.RU нужно проверить собственный PHP/FastCGI.

## Осталось проверить после отдельного разрешения

- Реальный CLI PHP 8.3, curl/mbstring/pdo_mysql, TLS и сетевые тайм-ауты на REG.RU.
- Реальную доставку личного сообщения именно владелице и разрешение сообщений от сообщества.
- Настоящие ограничения повторной отправки VK при потере ответа; бессрочная гарантия ровно одной доставки не заявляется.
- Минимальный интервал и фактическую работу cron, лимит длительности, наблюдение за его остановкой.
- Закрытый путь конфигурации/права файлов, HTTPS/FastCGI и cookie в настоящем браузере на домене.
- Резервное копирование, восстановление, согласованный срок хранения и очистку истёкших сессий/счётчиков.
- Обработку чрезмерно длинного уведомления: текст более 4096 символов получает failed без обрезания товаров; заказ остаётся в MySQL и закрытом просмотре.
- Перед активацией проверить накопленные pending-задания. Нельзя автоматически перепосылать failed с новым random_id без проверки факта доставки.

Публикация, миграции рабочей базы, commit, push и GitHub Actions не выполнялись.
