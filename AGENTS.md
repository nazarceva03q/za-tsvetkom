# Инструкции проекта «За цветком»

Перед работой прочитать docs/project/README.md. Если доступна полная локальная документация docs/private/project, сверить STATUS, DECISIONS и последние указания пользователя по ней. Публичная документация намеренно не содержит всех фактических настроек.

При каждом изменении в том же коммите обновлять соответствующую документацию и CHANGELOG. Полные факты и изменения настроек фиксировать локально; секреты и персональные/внутренние документы не добавлять в публичный GitHub. Не выдавать локальную подготовку за установку, а push — за проверенную публикацию.

Запуск форм отложен. Публикация юридических страниц его не разрешает. Не менять приватные enabled/UNAPPROVED, не отправлять уведомления РКН и не подписывать документы за владельца.

Сохранять постоянно работающие кнопки бота и защиту повторов. В панели две вкладки, без скачиваний и технических пояснений. Отдельный таймер черновиков отменён. Полный список согласованных решений — в закрытой локальной документации.

Для изменений интерфейса применять подходящие frontend-design и ui-ux-pro-max, изучать существующую структуру и DESIGN.md при наличии, сохранять дизайн, проверять результат. Не менять бизнес-логику ради оформления и не устанавливать зависимости без необходимости.

Не сливать рабочую ветку в main ради документа. Для публикации использовать точный список публичных файлов, проверенный корень и шифрованную передачу. Не коммитить config.php/.env, SQL-копии, реестры, подписи и закрытые договоры.
